# 性能の確認方法と確認範囲

## 実装した対策

毎フレームのフォント生成・画像読み込み・拡大処理をキャッシュし、通常素材を起動時に読み込みます。
描画ループの画面反映と`clock.tick(30)`を1フレームにつき1回へ統一しました。
DeepFaceは別スレッドで連続処理し、未処理フレームは最新1枚だけ保持します。

## これまでの確認

性能修正後の旧素材版をWindows実機で一周プレイし、利用者から動作に問題がなく、
表示された認識遅延が最大で約100msだったと報告されています。
CPU型番・測定時間・フレーム別記録は残っていないため、機種共通の性能保証や平均値としては扱いません。
新素材版の実機でのFPS・認識遅延の再確認は未完了です。

以前の描画単体比較にはタイトル130.0→3.83ms、対応表376.4→2.01ms、プレイ221.9→3.54msという記録があります。
測定スクリプト・ハードウェア条件を保存していない参考値であり、現行素材の性能やカメラ込みのフレーム時間とは区別します。

## カメラなしの画面出力

仮想環境のPythonで次を実行します。Pygameのみが必要です。

```bash
python -m tools.render_preview
```

タイトルと対応表を現行の描画関数から出力します。カメラ・DeepFace・実ユーザーデータを使いません。
これは画面の確認用であり、実際のプレイ動画や実推論の測定ではありません。

## 実機で測定する

1. ゲームを起動し、初回モデル取得・初期化後に認識が安定するまで待ちます。
2. タイトルで`E`→`N`→`H`を押すと開発者画面へ入れます。`R`で戻ります。
3. 表示FPSとフレーム時間、認識処理の遅延を記録します。
4. 通常プレイでもカメラ・入力・BGM・顔枠・判定が追従することを確認します。

認識遅延は処理にかかった時間であり、カメラ撮影から表示までの全遅延ではありません。
表示FPSは目標28 FPS以上、上限30 FPSです。CPU共有やカメラ取得による低下は実機で確認します。

記録する条件: OS、CPU、メモリ、Python、カメラ、ウィンドウサイズ、テーマ、測定時間、
平均FPS・最低FPS、認識遅延の平均・最大、モデルのウォームアップ有無。
